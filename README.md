# 皮蛋瘦肉舟 · 公共写作博客

一个零依赖的纯静态个人博客（HTML + CSS + 原生 JS），双击 `index.html` 即可打开，也可直接上传到任意静态托管。

**主题风格**：极简阅读型。文章**按年份归类**；每篇文章配一张**头图**（详情页大图 + 列表缩略图）；站点简介下方是一条显眼的**站内搜索栏**（边打边筛、命中高亮、相关度排序）；首页**右侧栏**是常驻的**赞赏 / 公众号支持区块**（跟随滚动，窄屏时落到列表下方）；标题走衬线、界面走无衬线；单一低调强调色（朱砂）；**不使用标签系统**。字体全部使用系统字体栈，**不依赖任何外部字体服务**（Google Fonts 在中国大陆无法访问，会拖慢加载）。

附带 **RSS 订阅**（`feed.xml`）、站点地图（`sitemap.xml`）与 `robots.txt`。

部署到自己的域名：见 [`DEPLOY.md`](./DEPLOY.md)。
备份与换电脑：见 [`BACKUP.md`](./BACKUP.md)。
**AI / 协作者开工前必读的项目硬约定：见 [`AGENTS.md`](./AGENTS.md)。**

## 目录结构

```
personal-blog/
├── index.html      # 首页：简介 + 订阅入口 + 搜索栏 + 按年份归类的列表 + 右侧支持栏
├── post.html       # 文章详情页（通过 ?id=xxx 渲染，含头图 + 分享按钮）
├── archive.html    # 归档页（按年份归类，仅标题，便于速览）
├── about.html      # 关于
├── 404.html        # 404 页面（部署后生效）
├── feed.xml        # ★ RSS 订阅源（由脚本生成，勿手改）
├── sitemap.xml     # ★ 站点地图（由脚本生成）
├── robots.txt      # ★ 收录规则（由脚本生成）
├── DEPLOY.md       # 部署到自有域名的分步指南
├── css/style.css   # 全站样式（含明/暗两套主题变量）
├── images/         # ★ 你的头图放这里（见 images/README.md）
├── drafts/         # ★ 文章草稿目录：把 .md 放这里，批量导入（见 drafts/README.md）
├── tools/
│   ├── build-feed.js    # 生成 feed.xml / sitemap.xml / robots.txt
│   ├── import-posts.js  # 把 drafts/*.md 批量导入 data.js，自动按日期倒序
│   └── import-wechat.js # 把公众号归档（Hugo 格式）转成 drafts/，顺带清理噪声
└── js/
    ├── data.js     # ★ 全站文章数据（唯一需要编辑的文件）
    ├── theme.js    # 明暗主题切换 + 移动端菜单
    ├── app.js      # 各页面的渲染逻辑（含分享按钮）
    └── vendor/
        └── qrcode.js  # 内置二维码库（MIT，只在点「微信」时才加载）
```

## 怎么发一篇新文章

只需编辑 `js/data.js`，在 `POSTS` 数组的**最前面**插入一个对象：

```js
{
  id: "my-new-post",                 // 唯一标识，会变成 post.html?id=my-new-post
  title: "文章标题",
  date: "2026-10-07",                // 用于排序与「按年份归类」
  excerpt: "列表页展示的一句话摘要。",
  cover: "images/my-new-post.jpg",   // 头图路径；留空 "" 会显示占位封面
  coverAlt: "头图的描述文字",         // 无障碍与 SEO 用，建议填
  content: `
    <p>正文段落。</p>
    <h2>小标题</h2>
    <blockquote>引用一段话。</blockquote>
    <ul><li>列表项</li></ul>
  `
}
```

保存后刷新页面即可——首页的年份分组、归档页、文章数都会自动更新。

### 然后重跑一次订阅源脚本

RSS 是静态文件，改了文章要重新生成一次：

```bash
node tools/build-feed.js
```

会同时刷新 `feed.xml`、`sitemap.xml`、`robots.txt`。

## 批量导入旧文章（推荐给「一次整理几十上百篇」）

如果你要一次性搬进来几年、几十上百篇文章，一篇篇手改 `data.js` 会很痛苦。
用 `drafts/` 目录 + 一条命令，**自动按日期倒序排好**。

### 步骤

**1. 把文章放进 `drafts/`**，一篇一个 `.md` 文件，文件名建议日期开头：

```
drafts/
├── 2018-04-22-巷口的豆浆摊.md
├── 2019-11-02-第一次记录.md
├── 2021-03-08-第二个秋天.md
└── _模板.md          ← 可复制它来写新文章
```

**2. 预览一遍，确认年份分组对不对：**

```bash
node tools/import-posts.js --dry-run
```

会打印每篇文章的日期、标题、id，以及按年份的统计。**先检查这一步有没有年份明显不对的**。

**3. 正式导入：**

```bash
node tools/import-posts.js --replace
```

**4. 重跑订阅源：**

```bash
node tools/build-feed.js
```

### 命令参数

| 命令 | 作用 |
|---|---|
| `--dry-run` | 只预览，**不写任何文件**。第一次用建议先跑这个 |
| `--replace` | `drafts/` 就是全部文章，`data.js` 里不在 drafts 中的会被清掉 |
| `--keep-existing` | 保留 `data.js` 里 drafts 中没有的文章，与 drafts 合并 |

不加 `--replace` 也不加 `--keep-existing` 时，如果发现 `data.js` 里有 drafts 中没收录的文章，
脚本会**停下来列出清单让你选**，不会擅自删东西。

### 发布前把关：头图裁切检查（强烈建议）

公众号导入（`import-wechat.js`）时，微信导出的 `cover.jpg` 常常是从正文第一张图里
**裁出来的一块**（宽高都被裁、还被压缩）。落库后就成了「头图是正文图的裁切版」——
详情页大图与列表缩略图用残缺版，正文里却还有完整版，既重复又别扭。

导入草稿、正式发布前，先跑一遍把关脚本：

```bash
python tools/guard-cover-crop.py            # 仅检查；发现裁切重复则退出码 1（可作发布闸门）
python tools/guard-cover-crop.py --fix      # 自动修复：把完整正文图提升为头图、删正文重复引用、旧封面移出（可恢复）
```

脚本用「多尺度 + 二维平移的归一化相关系数」判定，只会动「头图是某张正文图裁切」的文章，
其它文章一律不动。修复前自动备份草稿与旧封面。

### 文章文件怎么写

开头一段 `---` 写文章信息（**全部可省略，脚本会自动补**），后面用 Markdown 写正文：

```markdown
---
title: 楼下那家修鞋摊
date: 2024-05-12
excerpt: 一句话摘要，不写就自动取正文开头
cover: images/shoe-repair-stall.jpg
coverAlt: 街角修鞋摊，旧工具箱与木凳
id: shoe-repair-stall
draft: false
---

## 小标题

正文第一段会自动排版成「导语」，字号略大。

> 引用块

- 列表项
- 列表项
```

支持的 Markdown：`##` 标题、`>` 引用、`-` 列表、`**加粗**`、`*斜体*`、链接、图片、`---` 分隔线。

`draft: true` 或文件名以 `_` 开头 → **不导入**（想先攒着不发布时用）。

**完整字段说明见 [`drafts/README.md`](./drafts/README.md)。**

### 两个提醒

- **日期一定要有**。文件名开头写 `2024-05-12-`，或文件头写 `date: 2024-05-12`。
  两者都没有时，脚本会拿「文件修改时间」兜底——但你整理旧文章时，所有文件的修改时间
  其实都是**今天**，年份分组会全错。脚本遇到这种情况会**明确警告并列出文件清单**。
- **中文标题建议手动指定英文 `id`**。不写的话 id 就用中文，功能正常，
  但分享出去的链接会变成一长串 `%E4%B8%AD...`。脚本会提示哪些篇需要补。

### 删文章

**用 drafts 管理的**：删掉 `drafts/` 里那个文件，然后 `--replace` 重跑一次。

**手写进 `data.js` 的**：把那个对象从 `POSTS` 数组里删掉即可。

两种情况删完都要重跑 `node tools/build-feed.js`，否则 RSS 里还留着旧文章。

### 从公众号 / 其他博客批量迁移

如果你手上的文章是别处导出的（比如公众号归档工具生成的 Hugo 格式目录），
用 `tools/import-wechat.js` 先转成 `drafts/` 能吃的格式：

```bash
node tools/import-wechat.js "<归档目录>"
# 例：node tools/import-wechat.js "../wechat-archive/blog-output"
```

归档目录需要有 `content/posts/*.md` 和 `static/images/`。
它会做这些事：

- 配图复制到 `images/<slug>/`，并把正文里的绝对路径改成本站相对路径
- Hugo front-matter → 本站 front-matter（日期只取日期部分、`description` → `excerpt`）
- 提取头图（有 `cover.jpg` 用它，否则取正文第一张图，并把正文里那张删掉免得重复）
- **清理公众号噪声**：开头的「你真是个特别的人」关注引导、文末的「往期文章」微信链接、
  入群话术、二维码、原文 HTML 注释
- 输出报告：年份分布、无头图的篇目、正文偏短的篇目、仍带微信链接的篇目（供人工抽查）

跑完再照常执行 `import-posts.js --replace` 与 `build-feed.js`。

> 噪声清理靠关键词匹配，公众号模板千变万化，**不可能一次清干净**。
> 脚本会列出「仍含微信链接」的篇目让你抽查——那多半是正文里正常引用了原文，
> 也可能有漏网的。扫一眼 `drafts/` 里那几篇的结尾即可。

### 出错了怎么还原

每次导入都会自动把上一版存成 `js/data.backup.js`。
要还原就把 `data.backup.js` 改名覆盖回 `data.js`。

## 头图怎么加

1. 把你的图片放进 `images/` 目录（命名建议与文章 `id` 一致，如 `images/my-new-post.jpg`）
2. 在 `data.js` 里把该文章的 `cover` 填成 `"images/my-new-post.jpg"`

详细规格（尺寸、比例、体积）见 [`images/README.md`](./images/README.md)。

**没有图也不会破版**：`cover` 留空或路径写错时，会自动显示一枚按标题首字生成的占位封面，配色跟随站点主题。

## 捐赠按钮与公众号二维码

这两项在 `js/data.js` 的 `SITE` 里配置：

```js
donate: {
  url: "",                            // 外部赞助链接（爱发电 / PayPal.Me 等），留空则不出按钮
  image: "images/donate-qr.jpg",      // 赞赏码 / 收款码图片路径
  note: "如果这里的内容对你有过帮助……"  // 区块里的一句话文案
},
wechat: {
  name: "皮蛋瘦肉舟",                  // 公众号名称
  qr: "images/qrcode-wechat.jpg"      // 公众号二维码图片路径
}
```

配好后会出现在**四个地方**：

| 位置 | 形式 |
|---|---|
| **首页右侧栏** | 「支持这个博客」整段：赞赏码在上、公众号二维码在下，跟随滚动常驻；外链按钮（如有） |
| **关于页** | 同一段，接在「找到我」之后，二维码左右并排 |
| **每篇文章末尾** | 小支持条：「赞赏 · 关注公众号」，点击跳到首页右侧栏 |
| **页脚** | 「支持」链接 |

**图片从哪来**：

- 赞赏码：微信「我 → 服务 → 赞赏码」，或支付宝「收款码」
- 公众号二维码：微信公众平台后台 →「设置与开发 → 公众号设置 → 帐号详情 → 二维码」下载

图片放进 `images/` 后填路径即可（详见 [`images/README.md`](./images/README.md)）。

**不想展示怎么办**：把 `SITE` 里的 `donate: {...}` 或 `wechat: {...}` 整段删掉，
相关区块（含首页支持区块、文章末尾支持条和页脚链接）会自动消失。没填图片时会显示一个虚线占位框提示「待上传」，不会出现破图。

## 修改站点信息

同样在 `js/data.js` 顶部的 `SITE` 对象里改：

```js
const SITE = {
  title: "皮蛋瘦肉舟",                    // 站名
  subtitle: "面向公共写作，关怀真正的个体",  // 页脚副标题
  author: "皮蛋瘦肉舟",                    // 作者名（笔名）
  bio: "不沉醉宏大的叙事……",              // 关于页 / RSS 的一句话简介
  email: "",                              // 留空则页脚与关于页自动隐藏邮箱
  url: "https://你的域名.com",             // ★ RSS / sitemap 用它拼绝对链接
  startYear: 2026
};
```

> ⚠️ **换域名后一定要改 `SITE.url`，并重跑 `node tools/build-feed.js`**，
> 否则订阅源里的文章链接还指向旧域名。

## RSS 订阅

- 订阅地址：`你的域名/feed.xml`
- 每个页面的 `<head>` 都已加入 `<link rel="alternate" type="application/rss+xml">`，
  阅读器（Feedly、Inoreader、NetNewsWire 等）能自动发现
- 首页和页脚都有可见的订阅入口
- 订阅源**输出全文**（`content:encoded`），读者不必跳转即可读完
- **只输出最近 50 篇**（`tools/build-feed.js` 里的 `FEED_LIMIT`）。
  文章上百篇时，全文订阅源会到 1MB 级别，阅读器每次拉取都很慢。
  站点地图仍然收录全部文章，不影响搜索引擎收录。想给全量就改大这个数字

## 站内搜索

搜索栏就**在首页**（站点简介下方、文章列表上方），是一条带边框和底色的整条输入框，没有单独的搜索页。

- 边打字边筛，不需要按回车
- 多个关键词用空格分隔，**需要同时命中**才出现在结果里
- 检索范围包括标题、摘要和正文
- 结果按相关度排序（标题命中 > 摘要命中 > 正文命中），关键词会被高亮
- 搜索时列表从「按年份归类」自动切换为「按相关度排序」的扁平结果，清空输入框即恢复
- 当前关键词会同步到地址栏（`index.html?q=关键词`），可分享、可刷新、可收藏
- 在任意页面按 <kbd>/</kbd> 会跳到首页并聚焦搜索框

文章不多时，这是最省事的方案：**零依赖、零后端**，不引入任何搜索服务。
等文章多到几百篇、感觉筛选变慢时，再把检索逻辑换成预建索引即可（`searchPosts()` 是唯一的替换点）。

## 分享按钮

每篇文章正文下方都有一条分享栏，四个入口：

| 按钮 | 行为 |
|---|---|
| **微博** | 跳转微博分享页（带文章标题与链接） |
| **豆瓣** | 跳转豆瓣分享页（带标题与摘要） |
| **微信** | 弹出二维码浮层——用微信「扫一扫」打开本页，再点右上角 ··· 分享给好友或朋友圈 |
| **复制链接** | 一键复制文章地址（优先用剪贴板 API，失败回退到 `execCommand`） |

几点说明：

- **微信没有网页端分享接口**，这是官方限制，不是实现偷懒。所以只能给二维码让用户扫——这也是各家博客的通行做法。浮层里同时还给了「复制链接」和明文地址，二维码加载不出来也不影响分享。
- **二维码是本地生成的**：内置了 `js/vendor/qrcode.js`（Kazuhiko Arase，MIT 协议，56KB），**只在用户第一次点「微信」时才加载**，不拖慢文章页首屏；不请求任何第三方接口，断网也能用。
- 分享出去的地址取自浏览器地址栏（`location.origin + pathname + search`）。本地双击打开（`file://`）时会自动退回 `SITE.url`，**不会把本地文件路径分享出去**。
- 用手机自带浏览器打开时，微信装不上二维码扫描入口，直接点「复制链接」再粘贴到微信里最省事。

## 移动端适配

按主流手机实测宽度做过适配：iPhone SE/8（375）、iPhone 14/15（390/393）、Plus/Max（428）、安卓主流（360）、以及最窄的 320（iPhone 5/SE 一代）。

- **刘海屏**：`viewport` 带 `viewport-fit=cover`，左右用 `env(safe-area-inset-*)` 避开圆角与安全区；页脚底部额外留出 Home Indicator 的高度
- **触摸热区**：图标按钮 30px → 40px，导航菜单项与分享按钮都保证 ≥44px（iOS 人机界面的最小建议值）
- **不触发 iOS 自动缩放**：搜索框字号锁在 16px（小于 16px 时 iOS 聚焦输入框会自动放大整页）
- **断点**：960px 以下右栏落到正文下方；720px 以下进入手机版式（列表去缩略图、上下篇改单列）；400px 以下再收一档字号与内边距
- **长串不撑破**：全局 `overflow-wrap: break-word`，长网址不会把窄屏顶出横向滚动条
- 窄屏菜单加了 `max-height + 滚动`，横屏小手机也不会溢出屏幕

## 功能一览

- 文章列表**按年份归类**（年份作为分组标题）
- **批量导入**：把 `.md` 放进 `drafts/`，一条命令自动按日期倒序入库（见「批量导入旧文章」）
- 每篇文章配头图：详情页 16:9 大图、列表 4:3 缩略图；无图时自动降级为占位封面
- 文章详情页（含上一篇 / 下一篇导航）
- **首页站内搜索**（边打边筛、多词同时命中、命中高亮、相关度排序、地址栏同步）
- **分享按钮**：微博 / 豆瓣 / 微信（扫码）/ 复制链接，每篇文章底部都有
- **移动端适配**：刘海屏安全区、≥44px 触摸热区、三档断点（960 / 720 / 400）；顶栏与页脚全站等宽，翻页不跳动
- **RSS 订阅** + 站点地图 + robots
- 捐赠 / 赞赏码 + 微信公众号二维码（首页右侧栏、关于页、文章末尾、页脚四处；可整段隐藏）
- **排版细节**：首段当导语略大一号、行尾标点悬挂、朱砂细线引用块、列表用短横线标记、
  正文收尾一条居中细线、配了真图时头图下方显示图注（`coverAlt`）、标题折行自动均衡（`text-wrap: balance`）
- **打印 / 导出 PDF**：自动隐藏导航、搜索、分享、支持区块，正文转 11.5pt，外链地址会印出来
- 明暗主题切换（记忆用户选择，首次访问跟随系统）
- 顶栏毛玻璃 + 键盘焦点可见环（只在键盘操作时出现）
- 归档页按年份归类，仅标题便于速览
- 独立 404 页面
- 响应式布局，手机端可用（手机端列表自动切换为纯文字，保证摘要可读）
- 支持 `prefers-reduced-motion` 无障碍偏好
- 零外部依赖：无 CDN、无第三方字体、无框架

## 本地预览（可选）

双击 `index.html` 就能看。若希望用 `http://` 方式预览（例如测试分享链接、验证 `feed.xml` 能否被读取）：

```bash
cd personal-blog
python -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000
```

> 注意：`feed.xml` 里的链接用的是 `SITE.url`。本地预览时若想看到正确的绝对链接，
> 可临时把 `SITE.url` 改成 `http://127.0.0.1:8000` 再跑一次脚本。
